# V1 总结：多轮搜索 Agent 的可信基线

> V1 = Day 1～7。数据：HotpotQA validation 200 题（从 train 的 hard 题抽样，和 test 不重叠），检索范围是 HotpotQA 语料池（50.7 万段，**不是全量维基**），BM25，Qwen2.5-3B-Instruct。
> 主结果：贪心解码，代码标签 `v1-baseline`（结果运行 commit `0602ba7`，和标签处的方法代码逐字相同）。
> 细节见 `PROGRESS.md`（决策记录）、`BADCASES.md`（错题分类）、`LEARNING_NOTES.md`（面试问答）。

## 0. 一句话结论

**多轮搜索稳定地提高了证据召回（+11 个点，所有解码设定下都显著），但准确率没有稳定优势：错误从"搜不到"转移成了"读不对"和"停不准"。** 所以固定地多搜不划算，V2 要按题目动态决定怎么搜、什么时候停。

## 1. 介绍

### 30 秒版

> 我做的是一个多轮搜索 Agent 的可信评测框架，并在它上面研究"该花多少检索成本"。V1 在 HotpotQA 上对比了不检索、固定搜一次、Agent 自己多轮搜三种方法，所有方法共用同一套预算、解析器和评测器。结果是：多轮搜索把证据召回稳定地提高了 11 个点，但准确率的优势换一个采样种子就会翻符号，成本却是 4 倍。错题分析显示，多轮把"搜不到"基本解决了，错误转移到了"读不对"和"停不准"。所以下一步不是搜更多，而是按题目决定怎么搜、什么时候停。

### 2 分钟版（面试展开）

1. **问题**：Search-R1 这类方法让模型边想边搜，但只奖励答对，不管搜了几次。我关心的是算力分配：什么题值得多搜。
2. **框架**：四种方法共用一个循环、一个解析器、一个预算定义和一个评测器，只差"证据从哪来"。检索工具的接口拿不到题目编号，只有评测器能读答案，从结构上防泄漏。每次运行记录代码版本、配置和完整轨迹，代码没提交就拒绝运行。
3. **结果**：搜一次就把准确率从 12% 提到 32%，最划算；Agent 多轮再提 3.5 个点，但不显著。换 3 个采样种子重跑，差距在 −2 到 +4.5 之间，符号会翻。**真正稳定的是证据召回**：Agent 比固定搜一次高 8.5～12.5 个点，每个种子都显著。
4. **归因**：每道错题只归一个主因。固定搜一次的错误主要是搜不到（83 题），多轮把它压到 12 题；但 Agent 的错误里 57% 在阅读侧，还有 29 题是证据不够就停了。
5. **下一步**：V2 加多路检索和重排，用"这次搜索带来了多少新信息""模型对答案有多确定"这类信号，决定继续搜、换路还是停。

## 5. 案例

### 3 条成功案例：多轮搜索的价值在第二跳

选法：Agent 在贪心和 3 个采样 seed 下**全部答对**、Static RAG 4 次**全部答错**、而且答对靠的是第二次搜索补上的金标。满足这个严格条件的正好就这 3 题，都是桥接题。

| qid | 问题 | 第 1 次搜索 | 第 2 次搜索 | Agent | Static RAG |
|---|---|---|---|---|---|
| `5abb09c45542992ccd8e7ecc` | Trish Flavel 出生的郊区 2011 年人口多少？ | 找到 Trish Flavel 简介，读出出生地 Box Hill | "2011 census Box Hill suburb population" → Box Hill, Victoria | 9672 ✓ | 12562 ✗ |
| `5adc2ab45542994650320c99` | Johannes Bergion 所在的瑞典前卫金属乐队哪年成立？ | 找到 Johannes Bergion 简介，读出乐队名 | "Diablo Swing Orchestra formation year" → 乐队页 | 2003 ✓ | 1996 ✗ |
| `5abeef815542997ec76fd38f` | George Petros 担任特约编辑的低眉艺术杂志哪年创刊？ | 找到 George Petros 简介，读出 Juxtapoz | "Robert Williams Juxtapoz founding date" → Juxtapoz | 1994 ✓ | 1992 ✗ |

共同模式：**第二跳的实体不在问题里**，只有读了第一跳的段落才知道该搜什么。只搜一次的 Static RAG 拿不到第二段，就从手头的段落里挑了一个看起来像的数字。这正是 Day 2 检索体检的发现（原问题搜一次，前 3 条找齐两段金标的只有 28%）在真实轨迹里的样子。

### 3 条失败案例：多轮也会把题搞砸

| qid | 问题 | Agent 怎么错的 | 类型 |
|---|---|---|---|
| `5ac028855542997d642959d3` | Willie Almond 效力的 Football League 创始成员球队是？（金标 Accrington） | 第 1 次搜索就拿到了金标段落。之后继续用笼统的词搜（"founding member Football League"），搜来一堆无关球队的页面，最后说"文档里没写"。**Static RAG 拿着同一段金标、只搜一次就答对了** | 过度搜索：多搜带进来的噪声淹没了已有证据 |
| `5a77304b554299373536020f` | Germantown 沿着哪条政治分界线？（金标 Hudson River） | 第 1 次也搜到了金标。第 2 次查询写成 "Germantown Avenue political barrier"，模型已经认定了答案，最后答 Germantown Avenue。Static RAG 答对 | 查询带着错误假设，答案跟着查询走，没跟着证据走 |
| `5ae6af685542991bbc976166` | Shabbona 镇的州立公园以哪个印第安联盟命名？（金标 Council of Three Fires） | 只搜 1 次，读到部落名 Potawatomi 就作答，没有再查它所属的联盟。4 次解码都答成同一个错答案 | 过早停止，把中间答案当最终答案；一致但错 |

前两条是 Static RAG 在 4 种设定下都答对、Agent 都答错的 5 题中的两题：**同一个检索器，多给了模型自主权，它反而把本来能答对的题答错了**。第三条是 Agent 最常见的错因（过早停止，29 题）。

另一个值得记住的：`5a79c0d15542994bb9457063`（Kooskia 鱼类孵化场）上，Agent 和 Static RAG 拿到的 3 段证据完全相同，Agent 却答成了学名。**证据一样，只是呈现方式不同**（多轮工具返回 vs 直接放在问题前），阅读结果就不同。

## 6. V1 能说什么、不能说什么

**能说**：
- 多轮搜索稳定地提高证据召回（所有解码设定都显著）
- 只搜一次的主要瓶颈是第二跳，多轮把"检索器能力"类错误从 83 题压到 12 题
- 多轮的代价：输入 token 4.4 倍、P50 延迟 6.6 倍，而且结果对采样更敏感

**不能说**：
- "Agent 的准确率比 Static RAG 高"：EM 差距换 seed 会翻符号
- "宽松口径下显著"：只有 2/4 个设定显著（我曾经只看贪心就下了这个结论，后来用多 seed 推翻了）
- 任何关于全量维基、其他模型尺寸、test 集的结论：都还没跑

**局限**：
- 语料池是可控设定（50.7 万段），不是全量维基；比较题只有 41 题，按题型的结论置信区间很宽
- 错题分类是规则，人工核对 21 条有 17 条一致；"找到了但理解歪了"、别名、答案粒度规则判不出来
- 调过一次答案规范提示词，Agent 反而 −6 个点（77% 的轨迹被扰动），已回退；说明在 Agent 上逐条调提示词等于在噪声里调参

## 7. 对 V2 的启示

| V1 的发现 | V2 的对应设计 |
|---|---|
| 9% 的搜索 0 篇新文档；0 新文档的题多数是"这条路子卡住了" | 0 新文档 → **换路**（拆子问题 / 换检索器），而不是停 |
| 过早停止 29 题；采样一致性能标出其中 66% | 作答步答案一致性 × 证据侧信号 → 决定继续搜 / 换动作 / 停 |
| 过度搜索、检索干扰（Direct 会的 10 题被检索带偏） | 重排 + 控制证据量，不是越多越好 |
| BM25 让衍生页面压过实体页（Suicide Forest → Aokigahara） | Day 8 向量 / 混合检索、Day 9 重排 |
| 比较题把两个实体写进同一个查询，一个总排不进前 3 | 比较题按实体拆开搜 |
| 方法差距和解码波动同一量级 | 方法比较一律报贪心 + 3 个 seed，多数 seed 显著才算显著 |
