# V2 总结：按需升级的多跳检索（Day 8～12）

> 数据：HotpotQA（语料池 50.7 万段）和 2WikiMultihopQA（语料池 38.5 万段），都**不是全量维基**。模型 Qwen2.5-3B-Instruct，不训练。
> 检索：e5-base-v2 向量检索取 20 条候选 → bge-reranker-base 重排 → 前 3 条。
> 最终结果：**test 集，每组只跑一次**，贪心解码，结果运行 commit `59e53d4`。组、门槛、判定规则在跑 test 前预先登记（`DAY12_PREREG.md`，commit `8e23cde`）。
> 细节见 `PROGRESS.md`（决策记录、每一步的数字）、`LEARNING_NOTES.md`（原理和面试问答）、`day12_test_summary.json`（主表原始数）。V1 见 `V1_REPORT.md`。

## 0. 一句话结论

**全程让 Agent 多轮搜索，成本 4 倍以上，准确率却不显著优于"搜一次 + 重排"。改成"先搜一次，只在信号表明需要时多搜一次"（按需升级），两个数据集的 test 上都显著更好：零成本门控 +2.6～+2.8 个点、只多花约 50% token；每题让模型自己判断一次 +6.6～+7.1 个点、约 2 倍 token。**

## 1. 介绍

### 30 秒版

> V1 发现多轮搜索 Agent 搜得更全，但答得不比固定搜一次好，成本却是 4 倍。V2 先把固定流程做强：加向量检索和重排，只搜一次的准确率就从 30% 涨到 40%，这时多轮 Agent 已经完全没有优势。所以我把问题改成"什么时候值得多搜"，做了一个级联：先搜一次，用重排第 1、2 名的分差判断证据缺不缺，只把三成左右的题送去多搜一次。门槛和配置在 validation 上定好、多 seed 复查，跑 test 前预先登记，test 只跑一次。结果在两个数据集上都显著优于强基线，成本只多 50%；全量多轮 Agent 贵 4 倍还不显著。

### 2 分钟版（面试展开）

1. **出发点**：V1 的结论是"固定地多搜不划算"，错误从"搜不到"转移成了"读不对"和"停不准"。V2 要回答：什么时候该多花检索成本。
2. **先把基线做强**（Day 8～9）：加向量检索（Dense）、混合检索（Hybrid）、Cross-Encoder 重排。向量检索搜一次的召回就超过 BM25 Agent 搜多轮；重排把准确率从 0.300 提到 0.405，还抹平了检索器之间的差距。强基线 B3 = Dense + 重排 + 搜一次。在 B3 上，多轮 Agent 不再有任何优势，成本却是 4～5 倍。
3. **找到"值得多搜"的题**（Day 10）：只看问题做改写或拆解没用，2Wiki 组合题的桥接实体（问题里没出现、要第一跳才知道的名字）召回只有 7%。必须让模型**看到第一跳结果**再写第二个查询，组合题准确率 0.105 → 0.245。
4. **按需升级**（Day 11）：B3 先答 → 门控决定是否探测 → 探测时模型决定是否再搜。门控信号是重排第 1、2 名分差：零成本，AUC 约 0.74。系统设计成和已有运行逐字等价，贪心下可离线精确推算任意门槛，在线复核 200/200 一致。
5. **test 主实验**（Day 12）：预先登记后在没碰过的 test 上各跑一次，三条预期全部成立（见第 3 节）。

## 3. 主结果（test，贪心，每组只跑一次）

HotpotQA test 500 题（桥接 406、比较 94）；2Wiki test 800 题（4 类题型各 200，从官方 dev 抽，和 train 不重叠）。
"−B3" 为逐题配对 bootstrap（10000 次）的 EM 差和 95% 区间，单位是百分点；`*` = 区间下界 > 0。

| | HotpotQA EM | −B3 | 2Wiki EM | −B3 | 输入 token 倍数 | p50 延迟 |
|---|---|---|---|---|---|---|
| B3：搜一次 + 重排 | 0.360 | — | 0.299 | — | 1.00 | 约 315ms |
| 全量多轮 Agent | 0.378 | +1.8 [−2.6, +6.0] | 0.312 | +1.4 [−2.4, +5.1] | **4.25 / 4.51** | 约 1.7s |
| cascade 每题探测（rewrite） | 0.390 | +3.0 [+0.8, +5.4] * | 0.335 | +3.6 [+1.9, +5.4] * | 2.27 / 2.30 | 约 1.1s |
| **cascade 分差门控** | 0.386 | **+2.6 [+1.0, +4.4] \*** | 0.326 | **+2.8 [+1.5, +4.1] \*** | **1.54 / 1.45** | **约 330ms** |
| **cascade 每题 agent 探测** | **0.426** | **+6.6 [+3.0, +10.2] \*** | **0.370** | **+7.1 [+4.4, +9.9] \*** | 1.91 / 2.09 | 约 990ms |

- **质量–成本前沿上只有两个点**：要省成本用分差门控（只探测 30%～39% 的题，p50 延迟几乎不变，只有被升级的题拉长 p95）；要质量用每题 agent 探测。**全量多轮 Agent 被两者完全支配**：比它们都贵，又不比它们好
- 分差门控的门槛**是在另一个数据集上选的**（HotpotQA 用 2Wiki 上选的 4.19，2Wiki 用 HotpotQA 上选的 5.69），test 上没有重选

### 和预先登记的预期对照

| 预期（来自 validation） | test 结果 | |
|---|---|---|
| H1 分差门控 > B3：2Wiki 显著；HotpotQA 为正、可能不显著（validation 多 seed 0/3） | 两个数据集都显著 | ✅ HotpotQA 超出预期 |
| H2 每题 agent 探测 > B3：两个数据集都显著（validation 多 seed 各 2/3） | 两个都显著，且幅度更大 | ✅ |
| H3 全量多轮 Agent 不显著优于 B3，token ≥ 3 倍 | 不显著，4.25 / 4.51 倍 | ✅ |

### 稳健性：validation 上换 3 个采样 seed（temperature 0.7，和同 seed 的 B3 配对）

| −B3 | HotpotQA s1 / s2 / s3 | 2Wiki s1 / s2 / s3 |
|---|---|---|
| 分差门控 | +1.5 / +1.0 / +1.5（0/3 显著） | +2.6 / +3.0 / +3.9（3/3） |
| 每题 agent 探测 | +6.0 / +6.0 / +2.5（2/3） | +2.0 / +6.2 / +5.2（2/3） |

12 个格子全部为正。HotpotQA 上分差门控的收益在采样下偏小，test 上显著。如实报告：**它在 HotpotQA 上的效果是"小而为正"，不是每次都显著**。

## 4. 收益从哪来：两种升级各修一种错误

### 按题型（2Wiki test，每类 200）

| EM | 桥接比较 | 比较 | 组合 | 推理 |
|---|---|---|---|---|
| B3 | 0.495 | 0.515 | 0.120 | 0.065 |
| 全量多轮 Agent | **0.345** | 0.505 | **0.280** | 0.120 |
| cascade 分差门控 | 0.495 | 0.515 | 0.195 | 0.100 |
| cascade 每题 agent 探测 | 0.515 | **0.635** | 0.220 | 0.110 |

HotpotQA test：分差门控在桥接题上 0.357 → 0.387、比较题 0.372 → 0.383；agent 探测桥接 0.406、**比较题 0.511**。

- **分差门控修的是"证据不够"**：分差大 = 只有第 1 段特别相关，另一段多半没搜到。2Wiki 上收益几乎全在组合题（桥接实体第一跳拿不到）
- **agent 探测还能修"证据够了但读错"**：比较题两段证据通常一次就搜齐，B3 错在答案形式（yes/no 题答成国家名、答案多带了年份）。这类题分差很小，门控看不见；只有让模型自己看一眼、选择直接作答才能修
- **全量 Agent 在组合题上确实最强**（0.280），但在桥接比较题上从 0.495 跌到 0.345：B3 答对、它答错的 57 题里，28 题选了另一个选项，28 题的答案根本不是两个选项之一（问"哪部电影"却答了导演名字）。**多搜几轮会把答案带偏**，所以整体收益接近 0

### validation 上的收益拆分（Day 11.4～11.5）

agent 探测的收益 = "模型有把握时直接作答" + "真的再搜一次"：

| | 直接作答 | 再搜一次 |
|---|---|---|
| HotpotQA | +5.5 | +2.5 |
| 2Wiki | +2.1 | +2.3 |

"再搜一次"的收益在两个数据集上稳定（+2.3～+2.5）；"直接作答"的收益随数据集变化。单纯换作答格式（不让模型选择）没有用，2Wiki 上反而显著变差 −4.25，所以 B3 没改格式。

## 5. 案例（2Wiki test）

### 分差门控修好的组合题

1. *"What is the date of death of Leopold, Prince Of Hohenzollern's father?"*（金标 2 June 1885）
   B3 搜到的 3 段是 Leopold 本人、Leopold 公爵、Leopold 二世，答了别人的死亡日期。分差 6.29 > 门槛 5.69 → 探测，模型从第一段读出父亲是 Karl Anton，写出新查询 *"date of death of Karl Anton, Prince of Hohenzollern"* → 答对。
2. *"What nationality is Noemie Fox's mother?"*（金标 French）
   第一跳拿到 Noemie Fox 和两个同姓的人，B3 答 English。探测后查 *"What nationality is Myriam Fox-Jerusalmi?"* → 答对。同一题 agent 探测查成了 *"Felicia Fox nationality"*（追错了人），没答对：**第二个查询写得对不对，决定了升级有没有用**。

### agent 探测"直接作答"修好的比较题（证据本来就够）

3. *"Did the movies The Maker (Film) and Never Gone (Film), originate from the same country?"*（金标 no）
   两部电影的页面都在 B3 的前 3 条里，但 B3 答了 "United States"（把是非题答成了国家）。分差 4.84，门控不探测；agent 探测下模型直接答 "No" → 对。全量 Agent 搜了两轮后答 "Unknown"。
4. *"Which film was released first, Aas Ka Panchhi or Phoolwari?"*（金标 Phoolwari）
   B3 答 "Phoolwari (1946)"，意思对、EM 判错（多带了年份）。agent 探测直接答 "Phoolwari" → 对。全量 Agent 只搜了一部电影的上映日期，答了另一部。

### 全量多轮 Agent 把题弄坏（B3 本来对）

5. *"Which film has the director born earlier, Giallo A Venezia or Love And Hisses?"*（金标 Love And Hisses）
   B3 一次就拿到两部电影的页面，答对。全量 Agent 又分别搜了两位导演的出生年份，最后答了导演名 "Mario Landi"——**问的是电影，答成了人**。
6. *"Which film has the director born first, The Face Of Fu Manchu or The Hidden One?"*（金标 The Hidden One）
   B3 对；全量 Agent 把两个导演写进同一个查询，又单独搜了一次，答成另一部电影。agent 探测只追加了一个精确查询 *"Roberto Gavaldón birth year"*，答对。

## 6. V2 能说什么、不能说什么

**能说：**
- 在这两个多跳数据集、这个模型规模下，**按需升级在 test 上显著优于强固定基线**，两个数据集结论一致，门槛跨数据集迁移
- **全程多轮 Agent 不划算**：比强基线贵 4 倍以上，准确率不显著更高，被按需升级完全支配
- 重排第 1、2 名分差是一个零成本、跨数据集可用的"证据不够"信号（AUC 约 0.74）
- 收益可归因：门控修"证据不够"，模型自选作答修"证据够了但读错"

**不能说：**
- 不能说"Agent 没用"：全量 Agent 在 2Wiki 组合题上最好（0.280），只是在其他题型上的损失抵消了收益
- 不能外推到全量维基或更大的模型：检索范围是题目自带段落组成的语料池；3B 模型的阅读和答案形式问题很多，大模型上"直接作答"的收益可能不同
- 绝对准确率不高（test EM 0.30～0.43）：EM 口径严格，很多错是答案形式（多带年份、全称），F1 一起报
- HotpotQA 上分差门控的收益小，validation 采样下 3 个 seed 都不显著，不能说"每次都显著"
- 没有训练：所有结论都是不训练的提示词方法；V3 的 RL 才会碰"学会什么时候搜"

## 7. 对下一步的启示

- **两个信号组合**：分差门控（零成本、抓证据不够）+ 模型自评（多一次调用、抓读错）。现在的 agent 探测是"每题都调"，可以只在"分差小但模型不确定"时调，进一步压成本
- **答案形式是 3B 模型的大头损失**：比较题和桥接比较题的很多错是 yes/no 答成实体、多带年份、问电影答导演。可以加一个答案形式校验（问题问的是哪类东西）
- **第二个查询写得对不对决定升级有没有用**（案例 2）：V3 用 RL 训练时，奖励里可以加成本项，让模型学会"少搜、但搜准"
- **迁移到商品搜索**（Day 13～14）：同一套检索栈和预算框架，换成 Amazon ESCI 数据和 nDCG 评价，检验"按需花检索成本"在搜广推场景是否成立

## 9. 面试一分钟版

> V1 我发现多轮搜索 Agent 搜得更全，但答得不比固定搜一次好，成本还是 4 倍。V2 我先把固定流程做强：加向量检索和 Cross-Encoder 重排，只搜一次准确率就涨了 10 个点，这时多轮 Agent 已经完全没有优势。所以我把问题改成"什么时候值得多搜"，做了一个级联：先搜一次，用重排第 1、2 名的分差判断证据缺不缺，只把三成左右的题送去多搜一次，这个信号是零成本的。为了让结论可信，门槛是在另一个数据集上选的，validation 上用 3 个采样种子复查，跑 test 前把组和判定规则预先登记，test 每组只跑一次。结果在 HotpotQA 和 2Wiki 两个 test 上都显著优于强基线，+2.6 和 +2.8 个点，成本只多 50%；如果每题让模型自己判断一次要不要再搜，能拿到 +6.6 和 +7.1，成本约 2 倍。全程多轮 Agent 贵 4 倍以上，还不显著。按题型拆开看，门控修的是"证据不够"，模型自判还能修"证据够了但读错"，而全程多搜会在比较题上把答案带偏。
